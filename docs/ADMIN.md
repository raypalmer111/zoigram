# Веб-панель владельца Zoigram

Адрес: **https://vps-24654da6.vps.ovh.net/admin/**

Для входа используются логин и пароль аккаунта Zoigram. Настройки входа доступны в игре: Профиль → Редактировать → Вход и восстановление; см. ACCOUNTS.md.

Панель разрешена одному внутреннему UUID профиля, указанному владельцем сервера. Другие аккаунты не получают доступа к данным, даже если знают адрес страницы. Смена публичного ID, имени или UUID в запросе не даёт прав владельца. Токен входа из игрового мода не подходит для входа в панель.

## Разделы

- **Обзор** — игроки, публикации, комментарии, открытые жалобы и занятое фотографиями место.
- **Жалобы** — новые, закрытые или все обращения. Можно увидеть исходное фото, комментарий или профиль. Удаление контента из карточки жалобы также закрывает именно эту жалобу. Если автор уже удалил запись, жалобу можно закрыть отдельно.
- **Публикации** — фото с автором, подписью и реакциями. Поиск по подписи или номеру. Кнопка «Открыть» показывает полное фото и переход к комментариям.
- **Игроки** — поиск по имени, публичному ID или точному UUID; фильтр заблокированных аккаунтов. В профиле доступны смена ID, публикации и блокировка.
- **Комментарии** — поиск, переход к исходной публикации и удаление.
- **Журнал действий** — решение, дата, причина и автор. Для смены ID сохраняются прежний и новый варианты; для удаления — текстовый контекст записи. Фотография в журнале не дублируется.

## Как принимать решения

Каждое изменение требует причины и подтверждения в отдельном окне. «Отмена» ничего не меняет. Нажатие Enter в форме с незаполненной причиной не выполняет действие.

**Смена ID:** Игроки → найти аккаунт → Открыть → Изменить ID. Допускаются 1–24 буквы любого поддерживаемого языка, цифры или `_`, без `@`. Буквы приводятся к нижнему регистру, пробелы заменяются подчёркиваниями, декоративные символы удаляются. Укажите причину и сохраните. Занятые и прежние ID других аккаунтов назначить нельзя. UUID, логин, публикации и подписки сохраняются. Ручной ID остаётся до следующей смены имени игроком. Если другой запрос уже изменил ID, панель попросит обновить профиль.

**Creator:** Игроки → найти аккаунт → Открыть → Выдать Creator. Укажите причину и подтвердите. Игрок получает золотую корону и обводку аватара. Для отзыва используйте «Снять Creator» в том же профиле. Статус привязан к UUID и сохраняется при переименовании; доступа к панели модерации он не даёт. Собственный статус настроенного владельца назначается автоматически. Решения сохраняются в журнале, а устаревшая карточка не может перезаписать более новое решение.

В Zoigram 1.0 Creators этот статус также открывает кнопку «Активировать суперспособность» в собственном профиле игрока. Она даёт выбранному зою +10% к развитию навыка съёмки на 60 игровых минут. Перед активацией сервер заново проверяет статус Creator. Эффект не складывается и не добавляет опыт или уровень при нажатии кнопки. При истечении времени, перезагрузке мода или загрузке мира он снимается.

**Блокировка:** Игроки → Открыть → Заблокировать → причина → Подтвердить. Игрок теряет действующие игровые сеансы, а его публикации скрываются. Снятие блокировки возвращает видимость, после чего игрок может снова войти в Zoigram. Веб-панель не позволяет заблокировать своего владельца.

**Удаление:** откройте нужную публикацию или комментарий, нажмите «Удалить», проверьте содержимое, напишите причину и подтвердите. Удаление публикации также удаляет её комментарии и лайки. Это окончательное удаление из сообщества; кнопки восстановления в панели нет.

**Жалоба без нарушения:** нажмите «Закрыть жалобу» и укажите решение. Закрытую жалобу можно вернуть в очередь с новой причиной.

## Вход и сеансы

Сеанс панели действует до четырёх часов и хранится в защищённой HttpOnly-cookie. Выход из панели не завершает вход в игровой мод. После истечения сеанса войдите снова. Панель не сохраняет токены в localStorage и не включает административные ключи в мод.

При потере пароля используйте резервный код на странице входа Zoigram. Никому не передавайте серверный SSH-ключ или cookie браузера.

## Настройка сервера

В server/deploy/.env задаётся OWNER_PROFILE_ID — внутренний UUID существующего профиля владельца. Автоматического назначения первого пользователя нет. При переходе старый OWNER_STEAM_ID может временно находить прежний профиль в базе; Steam при этом не вызывается. OWNER_PROFILE_ID имеет приоритет. Если оба значения пусты, доступ отключён.

После изменения:

```sh
cd /opt/zoigram/Zoigram-server/deploy
sudo docker compose up -d --force-recreate api
```

Права проверяются по внутреннему UUID на каждом запросе, включая фотографии. Замена OWNER_PROFILE_ID лишает прежнего владельца доступа даже при ещё существующей cookie.

Сеансы панели хранятся в `admin_sessions`; историческая таблица `admin_logins` сохраняется для совместимости. Общий журнал `moderation` используется и веб-панелью, и серверными командами. В схеме 11 статусы Creator хранятся в `creator_grants`, прежние публичные ID — в `public_id_aliases`. Проверенная резервная копия должна включать эти таблицы. Перед обновлениями создавайте свежий снимок; инструкции по копиям находятся в docs/VPS.md проекта.

Тестовый стенд `tools/preview-admin.cjs` использует отдельную временную базу в памяти и только `127.0.0.1`. Он не входит в серверный архив или Docker-образ и не предназначен для публикации.

## ZoiMeet

В сервере 0.15.2 добавлен раздел ZoiMeet: подключения на связи за последние 20 секунд, известные устройства, ожидающие и принятые приглашения. Есть поиск по коду, страницы списков и обновление каждые 10 секунд. При потере связи данные помечаются как устаревшие.

Это просмотр соединений с сервером, а не доказательство общей игровой сессии. Профили и имена Zoigram не сопоставляются с кодами ZoiMeet. Административных действий над игроками ZoiMeet этот раздел не выполняет.

Доступ использует обычный сеанс владельца панели. Служебный ключ находится только на VPS в /opt/zoimeet/secrets/monitor.token и подключается к API-контейнерам для чтения. Браузер его не получает. Список не доступен по публичному API ZoiMeet. Дополнительный compose.override.yaml в папке развёртывания включает закрытый доступ панели; сохраняйте его при обновлении сервера.
